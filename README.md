# Практическая работа № 7

WPF-клиент для API лекарств из практической работы № 6. Это отдельный проект `pract7`: .NET 8, MaterialDesignThemes 5.1.0.

## Запуск

1. Открой проект API из практической работы № 6 в Visual Studio и запусти его. Проверь в Swagger, что GET `/api/v1/Medicines` возвращает данные из базы.
2. Открой `pract7.sln` во втором окне Visual Studio. Нужны .NET 8 SDK и компонент «Разработка классических приложений .NET». Восстанови пакеты NuGet и запусти проект.
3. В поле «Адрес API» укажи адрес запущенного API, например `https://localhost:7001`. Порт возьми из адреса Swagger; `/swagger/index.html` в это поле не добавляй.
4. Нажми «Обновить список». API должен оставаться запущенным во время работы клиента. Строка подключения к SQL Server настраивается в проекте API, клиент обращается к нему через HTTP.

Если HTTPS сообщает об ошибке сертификата, используй настроенный HTTP-адрес API или доверь сертификату разработки через `dotnet dev-certs https --trust` на своём компьютере.

## Страницы

- `MainWindow` содержит только `MainFrame` и открывает `MainPage` через `MainFrame.Navigate`.
- `MainPage` показывает каталог, адрес API и фильтры. Здесь находятся запросы HttpClient и свойства для привязки данных.
- `AddPage` содержит форму нового лекарства.
- `EditPage` получает запись по Id и позволяет изменить или удалить её.

Кнопки «Открыть выбранное» и «Добавить лекарство» открывают страницы внутри того же Frame. Кнопка «Назад к каталогу» возвращает список. Все данные элементов интерфейса передаются через Binding.

## Запросы

| Действие | Запрос |
| --- | --- |
| Список | GET `/api/v1/Medicines` |
| Фильтры на сервере | GET `/api/v1/Medicines?manufacturer=...&available=true` |
| Одна запись | GET `/api/v1/Medicines/{id}` |
| Добавление | POST `/api/v1/Medicines` |
| Полное изменение | PUT `/api/v1/Medicines/{id}` |
| Частичное изменение | PATCH `/api/v1/Medicines/{id}` |
| Удаление | DELETE `/api/v1/Medicines/{id}` |

API должен поддерживать параметры `manufacturer` и `available`. Фильтрация выполняется сервером, клиент передаёт выбранные значения в запросе.

Для PUT заполни все поля. Для PATCH отметь только поля, которые нужно изменить: в JSON попадут только они. Например, чтобы снять наличие, отметь «Изменить наличие при PATCH» и убери галочку «Есть в наличии». PATCH ожидает обычный JSON-объект с необязательными полями, а не массив операций JSON Patch.

Дата вводится в формате `2027-12-31`. Цена принимает точку или запятую, не больше двух знаков после разделителя. Пустые обязательные поля, неверная дата и отрицательная цена не отправляются. Удаление требует подтверждения. После изменения клиент заново получает список; после PUT/PATCH также получает обновлённую запись.

Ошибки ввода, ответы API и проблемы подключения показаны внизу страницы. Пока выполняется запрос, кнопки и поля заблокированы. Если ответ не пришёл вовремя, сначала обнови список: сервер мог успеть сохранить изменение.
